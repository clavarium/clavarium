A conversation's machine

Looked at, put back when a folder comes loose, restarted on request. A machine asleep is never woken.

  • Asked first. Restart and a new size ask before stopping anything.
  • Per conversation. Memory and disk are in its settings; the record keeps what multipass says it has.
  • Untouched: its work folder, its folders, its branches.
  • In its chat too. Where the agent talks through the app, what is wrong is also a grey line in the thread, where it happened, kept, with the same buttons; a restart is said there, and the agent, back with nothing of the chat in mind, is told once to read it whole (parley read --all). The page never puts the terminal in front by itself.
  • No restart offered while it starts. Only when its machine is not well, or the wait is far longer than a start (3 min).
  • A terminal that does not come, though its machine runs: after 30 s the server closes the channel, keeps the agent's tmux if it answers (stops it otherwise) and opens it again; only if it still does not come is a restart offered, in plain words. A machine still starting is waited for, and the page tries again by itself.
  • On its last session. Each tool has a resume line in config/tools.json (claude --continue...), used at each start but the first on a disk, unless the owner chose "Start fresh".
  • /tools, read-only, in every machine. What an agent may install by itself when asked (Parley first): archives and an index (name, version, sha256, one line of usage), kept by the server, shown through a read-only view like a read attachment, looked at and put back like the other folders.
