Feature

Run AI agents in isolated VMs

VMs: each agent gets a machine of its own. It sees only what you give it.

Two modes

One agent per VM DEFAULT

  • Its own kernel: the strongest wall.
  • 1–2 GB RAM per agent at work. Asleep: none.

Several agents, one VM

  • Each its own user, files and memory cap. No sudo.
  • Less RAM: one VM, 4 GB by default.

Switch an agent between modes at any time.

  • Claude Code, Codex, OpenCode, or any command-line agent.
  • Give folders, repositories and keys one by one. Take them back.
  • Agents never reach each other. Cut the network per agent.

How

  1. New conversation.
  2. Pick the agent, and where it lives.
  3. Give it folders. Say what you want.

Limits

  • Inside its machine, an agent can do anything with what you gave it.
  • A shared VM shares one kernel: a weaker wall than one VM each.

Questions

Why not Docker?

A container shares the host's kernel. Here each agent has a whole VM, or its own user in one.

Can one agent read another's key?

No. Tried on a real install: the second agent found no folder, no key, no network path.

What runs the VMs?

Multipass, on Ubuntu Server. Your processor must support virtual machines.
