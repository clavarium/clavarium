Feature

Keys & assets: give an agent only what it needs

Secrets, folders, accounts: each to one agent, with a right. Taken back with one tap.

Keys and secrets

A key you give one agentIn that agent's machine, in memory, only while it runs. Detach it: removed at once. A copy it already made stays.in its machine
The key that pushes codeSealed on your server. Used when you press Send.never in a machine
Mail and account passwordsSealed on your server. The connector acts for the agent.never in a machine

Then everything else

  • FoldersRead or write. Read-only enforced outside.
  • Git repositoriesCommits sent after your review.
  • MailboxesGoogle, Microsoft, IMAP.
  • Calendars, contactsGoogle, Microsoft, CalDAV.
  • MCP serversTheir key stays with Tether.

How

  1. Add the asset once.
  2. Attach it to a conversation: read, write or use.
  3. Detach it when done.

Limits

  • A key given to an agent can be read by that agent.
  • A folder given to write, it can change.

Questions

Can two agents share a folder?

Yes, each with its own right. That is how agents hand work to each other.

Does the agent see my Google password?

No. The token stays sealed on the host; the connector acts for the agent.

I changed a key. Do I restart?

No. The agent's copy follows within a minute.
