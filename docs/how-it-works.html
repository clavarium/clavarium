How it works

The pieces of Clavarium, one picture each.

A git repository: one reference, the key stays on the server

The agent never holds the key. It only reads from the reference and commits in its own folder.

uses the key (on the server)no key, nothing runread only, from the machine
  1. GitLab to the reference: the server fetches what is new, with the key.
  2. The reference to the agent: the agent fetches it itself, read only.
  3. The agent to the reference: the server fetches its commits; only commits travel, never its hooks or settings.
  4. The reference to GitLab: the server pushes, after your review, or by itself to the branches you allowed.
