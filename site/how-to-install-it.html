How you install it

One command, parameters only. It asks nothing, and can be run again to upgrade.

What it needs

  • A small machineUbuntu Server 24.04 or 26.04, on a processor that can run virtual machines. A mini PC does.
  • 1 to 2 GB of memory per agent at workand a few GB of disk each. An agent asleep costs no memory. Tried on 4 cores, 6 GB, 40 GB.
  • A name for itA domain or a sub-domain of yours, pointing to the machine, or to its relay.
  • An AI of yoursA subscription (Claude, ChatGPT), or a key from a service that hosts models. clavarium brings none and charges nothing.

On the machine

From the folder of the source:

sudo deploy/install.sh \
  --domain clav.example.com \
  --operator you@example.com
  • An account that owns its data and nothing else, and the one program it may run with more rights.
  • The address in https, a sign-in in front of everything, and a password for each operator, shown once.
  • The key that opens the sealed secrets, kept apart from the data.
  • Each piece it downloads is a named release, checked against a checksum written in the script.

To try it first, with no domain

On an Ubuntu machine of your own. No name, no sign-in: the page answers on that machine only.

sudo deploy/install.sh --local

# from another computer of yours
ssh -L 7717:127.0.0.1:7717 you@that-machine     # then http://127.0.0.1:7717
  • Whoever can open a page on that machine is its operator: not for a machine other people use.
  • For real use, run the installer again with a domain and an operator.
  • Not yet run on a fresh machine: see the end of this page.

No public address at home?

The machine at home dials out to a small machine that has one. Home opens no port.

# at home
sudo deploy/install.sh --domain clav.example.com \
  --operator you@example.com --relay relay.example.net

# on the relay, with the line the first command printed
sudo deploy/relay.sh --key "ssh-ed25519 AAAA…"
  • The relay carries bytes. Encryption starts in your browser and ends at home.
  • It holds no certificate and no secret of yours.
  • One record in your domain keeps whoever runs the relay from obtaining a certificate for your name; the script says which.

Then, your agents

  • Claude Code: you sign in once in its terminal, with your own subscription.
  • OpenCode: with the key of a service that hosts models; tried with open models hosted in Europe.
  • Another agent that runs in a terminal: one entry in config/tools.json (its name, its command, how to install it).

Two things that need a key of yours

  • Dictation: a service that turns speech into text.
  • Answers while you are away: a service that hosts several models.
  • Both are optional, set on the machine, and can be the same key.

Keeping it

sudo deploy/backup.sh --to /path/to/a/folder
sudo deploy/restore.sh ARCHIVE.tgz --check     # reads, changes nothing
sudo deploy/restore.sh ARCHIVE.tgz --vault-key FILE
  • Two files, to keep in two places: the archive, and the key that opens its secrets.
  • A restore that does not come back up puts back what was there.
  • Not in a backup: the machines of the agents. What must outlive one belongs in an attached folder.

What was really tried

  • The installer, on a fresh Ubuntu 24.04 and a fresh 26.04.
  • The relay, on a real one, with a machine at home behind it.
  • A backup, a restore, and a restore that fails and puts things back.

What was not, yet

  • A certificate obtained by the installer on a machine with its own public address.
  • A mailbox at one of the large mail providers.
  • The mode to try it without a domain (below): written and tested as far as tests go, not yet run on a fresh machine.
